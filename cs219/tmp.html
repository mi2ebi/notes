multi cycle implementation is not always faster than single cycle!

but we can try something else...

pipelining
overlapping execution of multiple instructions/steps

a nice analogy is doing laundry. if you have, say, 3 loads of laundry to do, instead of

  • doing the entire first load
  • doing the entire second load
  • doing the entire third load

you can save a lot of time by

  • putting the first load in the washer
  • when it's done, moving it to the dryer and starting the next load
  • etc

buuuuut moving stuff between the washer and dryer takes time! (overhead)

we want CPI to be as close to 1 as possible

pipelining does come with hazards, eg the same processor unit can't be used twice in the same cycle

control hazard
branches and jumps
data hazard
dependencies between instructions
WaR (write after read)
RaW (read after write)
WaW (write after write)
structural hazard
resource conflicts
