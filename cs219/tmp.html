pipelining

multi cycle implementation is not always faster than single cycle!

but we can try something else...

pipelining
overlapping execution of multiple instructions/steps

a nice analogy is doing laundry. if you have, say, 3 loads of laundry to do, instead of

  • doing the entire first load
  • doing the entire second load
  • doing the entire third load

you can save a lot of time by

  • putting the first load in the washer
  • when it's done, moving it to the dryer and starting the next load
  • etc

buuuuut moving stuff between the washer and dryer takes time! (overhead)

we want CPI to be as close to 1 as possible

hazards

pipelining does come with hazards, eg the same processor unit can't be used twice in the same cycle

control hazard
branches and jumps
data hazard
dependencies between instructions
WaR (write after read)
RaW (read after write)
WaW (write after write)
structural hazard
resource conflicts

2026-03-31

to prevent overlapping stages, the result of each stage is stored into a buffer until the clock says "hey do the next part now"

mips has 32 registers but usually we only need up to 19 of them (s0-7, t0-9, zero)

if you have eg

lw $t0, 4($t1)
add $t3, $t0, $s0

then with pipelining...

     1 2 3 4 5 6
lw:  F D E M W
add:   F D E M W

in cycle 5, lw is writing into $t0. but add reads the garbage value of the register in cycle 3! this is a RaW data hazard

or:

sub $t4, $t5, $t3
add $t5, $t2, $t3

$t3 is being read both times, which isn't a problem. RaR isn't a hazard

     1 2 3 4 5 6
sub: F D E M W
add:   F D E M W

sub cycle 2 needs to read $t5. add cycle 6 needs to write to it. this isn't a problem for either of these instructions. but if there's a third instruction it might be! it's not a threat but it is a WaR hazard

or:

sub $t6, $t5, $t3
add $t6, $t2, $t3

again $t3 is being read both times which is ok.

     1 2 3 4 5 6
sub: F D E M W
add:   F D E M W

this is also not a threat, but it is a WaW hazard
