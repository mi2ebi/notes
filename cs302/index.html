linked lists

each node of a (doubly) linked list has

  • pointer to the previous element
  • the actual data
  • pointer to the next element

there's also a pointer head pointing to the start of the list, and likewise for tail pointing to the end 

class Node {
  public:
    int data;
    Node *prev;
    Node *next;

algorithms

algorithm
process to solve a problem, in general, with finite time

to measure time we can

  • call eg time on linux to get the amount of real time (not super useful)

asymptotic complexity classes

big O

\(g(n) = O(f(n))\)
iff \(g(n) ≤ cf(n)\) for some \(c > 0\) and \(n ≥ n₀ > 0\)

complexity notation
constant \(O(1)\)
logarithmic \(O(\log n)\)
linear \(O(n)\)
polylogarithmic \(O(\logᵏ n)\)
quadratic \(O(n²)\)
exponential \(O(aⁿ), a > 1\)

examples

  • \(n = O(n)\)
  • \(3n = O(n)\)
  • \(1000n = O(n)\)
  • \(1000n + 23 = O(n)\)
  • \(\sqrt n = O(n)\) ...this is sort of weak

big O gives an upper bound

big Ω

\(g(n) = Ω(f(n))\)
iff \(g(n) ≥ cf(n)\) for some \(c > 0\) and \(n ≥ nₒ > 0\)

big omega is a lower bound

examples

  • \(n = Ω(n)\)
  • \(3n = Ω(n)\)
  • \(5n² = Ω(n)\) ...this is also weak

big Θ

\(g(n) = Θ(f(n))\)
iff \(g(n) = O(f(n))\) and \(g(n) = Ω(f(n))\)

examples

  • \(n = Θ(n)\)
  • \(7n = Θ(n)\)
  • \(3n² ≠ Θ(n)\) because it's \(Ω(n)\) but not \(O(n)\)

logs

for time complexity the log base doesn't matter. even though in Real Math \(\log x = \log₁₀ x\) or \(\ln x\) depending who you ask

\(\logₐ n = Θ(\log n)\) regardless of \(a\)

\[\logₐ n = \frac{\log_b n}{\log_b a}\]

calculus

\[\lim_{n → ∞} \frac{g(n)}{f(n)}\]

this could

  • go to infinity, in which case \(f\) can't keep up with \(g\) at all
    \(g(n) = Ω(f(n))\)
  • be a constant bigger than 0, in which case \(g\) and \(f\) have the same growth rate
    \(g(n) = Θ(f(n))\)
  • be zero, in which case \(f\) is strong enough to pull \(g\) down to zero
    \(g(n) = O(f(n))\)

l'hôpital's rule says

\[ \lim_{n → ∞} \frac{g(x)}{f(x)} = \lim_{n → ∞} \frac{g'(n)}{f'(n)} = ⋯ \]

eg does \(n² + 33n + 2 = O(n)\)?

using normal math: \[ \lim_{n → ∞} \frac{n² + 33n + 2}n = \lim_{n → ∞} \left(n + 33 + \frac2n\right) = ∞ \]

using l'hopital's: \[ \lim_{n → ∞} \frac{n² + 33n + 2}n = \lim_{n → ∞} (2n + 33) = ∞ \]

therefore \(n\) is not an upper bound for \(n² + 33n + 2\)

does \(\sqrt n = O(\log n)\)?

\[ \lim_{n → ∞} \frac{\sqrt n}{\ln n} = \lim_{n → ∞} \frac n{2 \sqrt n} = \lim_{n → ∞} \frac{\sqrt n}2 = ∞ \]

no

logs are very nice for runtime

binary search

bool find(int a[], int n, int s) {
  int l = 0;
  int r = n - 1;
  int m;
  while (l <= r) {
    m = l + (r - l) / 2; // O(1)
    if (a[m] == s)       //
      return true;       //
    if (a[m] < s)        //
      l = m + 1;         //
    else                 //
      r = m - 1;         //
  }
  return false;
}

worst case, s isn't in the array at all

sorting

insertion sort

void insertionSort(int a[], int n) {
  for (int i = 1; i < n; i++) {
    int key = a[i];
    int j = i - 1;
    while (j >= 0 && a[j] > key) {
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = key;
  }
}

after every iteration of the outer loop, the slice of the array from 0 to i - 1 is always sorted

the inner loop makes room for the key to be inserted

worst case, the list of reversed and j has to go all the way to -1 every time

this is a nice \(\frac n2 (n - 2)\) situation, so it's \(Θ(n²)\). not great

best case, it's already sorted and the inner loop never runs

then it's just \(Θ(n)\)

merge sort

'divide and conquer' algorithm, which unfortunately necessitates recursion

  • split the array into 2 pieces (the left side and the right side)
  • recursively mergeSort each half to get two sorted half arrays
  • merge the halves
void mergeSort(int a[], int l, int r) {
  if (l >= r)
    return;
  int m = l + (r - l) / 2;
  mergeSort(a, l, m);
  mergeSort(a, m + 1, r);
  merge(a, l, m, r);
}
void merge(int a[], int l, int m, int r) {
  int i = l, j = m + 1, k = 0;
  int b[r - l + 1];
  while (i <= m ** j <= r)
    if (a[i] <= a[j])
      b[k++] = a[j++];
  while (i <= m)
    b[k++] = a[i++];
  while (j <= r)
    b[k++] = a[j++];
  for (int x = 0; x < r - l + 1; x++)
    a[l + x] = b[x];
}

merging all the arrays at a given level together is \(Θ(n)\), and there are around \(\log₂ n\) levels

which means it's better than insertion sort!

lower bound for comparison-based sorting

suppose in the worst case the lower bound is \(Ω(n)\). then we could run faster than \(O(n \log n)\) in the worst case. problem is we don't know of any sorting algorithm better than \(O(n \log n)\) in the worst case

suppose in the worst case the lower bound is \(Ω(n \log n)\). then sorting is a closed problem and we've solved it

say we have a list \([a₁a₂a₃]\). if we make a tree of all the possibilities, there are 6 ways they could be arranged and the height of the tree is 3. so there's no way to sort a list in less than 3 comparsions

so the lower bound for sorting is the height of our tree

it's close enough to just say \(h = \log₂(\text{\# leaves})\). how many leaves are there?

permutation
number of ways to arrange a list

for an array of length \(n\) there are \(n!\) permutations

so \(h = \log₂ (n!)\). we know from doing some loops that that's \(O(n \log n)\)

therefore the lower bound of comparison-based sorting is \(Ω(n \log n)\)

traversing

more recursion! base case is the tree being empty. recursive case is a node where left and right point to a smaller binary tree

there are a couple different ways to traverse a tree

void preorder(BinTreeNode* r) {
  if (r == nullptr)
    return;
  cout << data; // preorder process
  preorder(r->left);
  preorder(r->right);
}
void postorder(BinTreeNode* r) {
  if (r == nullptr)
    return;
  postorder(r->left);
  postorder(r->right);
  cout << data;
}

binary search trees

search structure

a bit like having folders!

template <class K, class V>
class BinTreeNode {
  public:
    K key;
    V value;
    BinTreeNode<K, V>* left;
    BinTreeNode<K, V>* right;
}

for each node \(r\):

  • r->left's key is less than r's key
  • r->right's key is larger than r's key

searching

template <class K, class V>
bool find(BinTreeNode<K, V>* r, K k) {
  if (r == nullptr) return false;
  if (k == r->key) return true;
  if (k < r->key)
    return find(r->left, k);
  return find(r->right, k);
}

the function body is constant time. for here we only have to check one node per height level at most

best case the runtime is \(Θ(\log n)\) if the tree is perfectly balanced. worst case it's \(O(n)\) if it's perfectly unbalanced

the insertion order determines the height of the tree

so the question is can we have the tree balance itself?

avl trees

this is a self-balancing binary search tree. when we insert or delete we balance the tree if needed

how do we know if a tree is balanced? for each node the difference in its left and right subtree heights cannot exceed 1

this requires adding a size_t height into BinTreeNode

the empty tree has a height of -1. for every node \(r\) its height is \( \max( r\mathord→\mathrm{left}\mathord→\mathrm{height}, r\mathord→\mathrm{right}\mathord→\mathrm{height} ) + 1 \)

to fix imbalanced trees we can rotate them

if the tree still isn't balanced, via a zigzag, we need to double rotate instead. we perform an intermediate rotation on one of the subtrees to align the tree

eg inserting \([75, 50, 90, 40, 60, 100, 55, 65, 52]\)

runtime!

  • finding the vacancy in the tree takes \(h\) steps
  • each rotation is constant time
  • we perform at most 2 rotations
  • so maintaining balance requires no overhead!

worst case, for each node except the leaves, the difference of its left and right subtree heights will be exactly 1: \[ \begin{align*} N(h) & = N(h - 1) + N(h - 2) + 1\\ N(-1) & = 0\\ h & ≈ \sqrt 2 \, \log₂ n = O(\log n) \end{align*} \]
